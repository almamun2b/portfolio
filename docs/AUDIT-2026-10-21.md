# Portfolio audit (pre-launch)

**Date:** 2026-10-21 · **Branch:** `feat/new-portfolio` · **Commit:** `80be910` · **Scope:** the whole app (code, content, SEO, performance, accessibility, security, tooling, deploy), checked against a production build.

It supersedes the 2026-10-06 audit of the empty `create-prisma` scaffold (removed; see git history). Every finding there is closed or carried over here.

---

## Verdict

The code is in good shape: strict types, lint and format clean, a typed content layer, sensible primitives on native elements, and no console errors or layout shift. **Four things should be fixed before this branch replaces the live site:**

1. **Every URL of the current live site breaks at launch.** `portfolio-mamun.vercel.app` still serves the old portfolio, whose indexed URLs (`/about-me`, `/project/*`, `/contact-me`, `/blog/*`, `/mamun.pdf`, …) all return 404 on the new build. No redirects exist.
2. **The four main pages have no social preview image.** `/`, `/about`, `/projects` and `/contact` render no `og:image` or `twitter:image`, so links shared on LinkedIn, X or Slack show no card image.
3. **The Three.js background can make the site unusable.** On machines without GPU acceleration it drops the page to **4–8 fps** with about 3 s of main-thread blocking, and it never checks for that case. It also runs a 60 fps loop forever on every device.
4. **The contact form doesn't reliably deliver a message.** It only opens a `mailto:` link. Visitors on webmail with no mail app configured (most desktop recruiters) see "Your email app should now be open…" while nothing happens.

The next tier is page weight (the home page HTML is **945 KB**, 147 KB gzipped), a non-functional chatbot in the most prominent spot on every page, and dates that freeze at build time.

### 2. Main pages have no social preview image

Only project pages and the 404 page get an `og:image`. Verified on the production build:

| Page               | `og:image` | `twitter:image` |
| ------------------ | ---------- | --------------- |
| `/`                | ❌         | ❌              |
| `/about`           | ❌         | ❌              |
| `/projects`        | ❌         | ❌              |
| `/contact`         | ❌         | ❌              |
| `/projects/[slug]` | ✅         | ✅              |
| 404                | ✅         | ✅              |

**Cause:** `src/app/opengraph-image.tsx` attaches its image to the root layout's `openGraph`. Every page calls `pageMetadata()` ([metadata.ts:24](../src/lib/metadata.ts#L24)), which returns a new `openGraph` and `twitter` object. Next merges metadata per top-level key, so the page's objects replace the layout's and the inherited image is dropped.

**Fix:** have `pageMetadata` add `images` (default `/opengraph-image`, 1200×630, with alt) to both `openGraph` and `twitter`. Project pages keep their own: their `opengraph-image.tsx` sits deeper in the tree and takes precedence. Better still, give `/about`, `/projects` and `/contact` their own generated cards (the `OgFrame` helper makes this cheap). Recheck with `curl -s <url> | grep og:image`.

### 3. Three.js background: no performance guard

[scene.ts:121](../src/components/effects/constellation/scene.ts#L121) creates the renderer with `antialias: true` and no `failIfMajorPerformanceCaveat`, then runs `tick` on every animation frame forever ([scene.ts:172](../src/components/effects/constellation/scene.ts#L172)). It only pauses when the tab is hidden.

Measured on `/` at 1440×900, no CPU throttle, software WebGL:

| Scenario                     | Long tasks (5 s) | Blocking time | Max task | fps |
| ---------------------------- | ---------------- | ------------- | -------- | --- |
| As shipped                   | 12               | 3,232 ms      | 993 ms   | 4   |
| Three.js chunk blocked       | 4                | 631 ms        | 314 ms   | 20  |
| Reduced motion               | 4                | 206 ms        | 168 ms   | 61  |
| `/contact` as shipped        | 26               | 3,155 ms      | 568 ms   | 8   |
| `/contact`, Three.js blocked | 2                | 214 ms        | 201 ms   | 61  |

Even with Three.js gone, the CSS motion (blurred glows animated with `glow-float`, orbit, marquee, many `backdrop-filter` layers) still holds the page at about 20 fps in software rendering.

**Fix, in order of value:**

- Pass `failIfMajorPerformanceCaveat: true` to `WebGLRenderer`. Context creation then fails on software rendering, and the existing `try/catch` already falls back to the CSS glows.
- Skip the scene on small screens, `navigator.hardwareConcurrency <= 4`, or `navigator.deviceMemory <= 4`. The phone gets 60 particles but pays the same frame loop and a 134 KB (gzipped) download.
- Cap the loop at 30 fps, use `antialias: false` (DPR is already capped at 1.5), and stop it after the first 20–30 s with no pointer movement.
- Consider dropping `backdrop-filter` on the sticky header and the animated blurred glows on touch devices.

### 4. The contact form doesn't reliably deliver

[contact-form.tsx:45](<../src/app/(site)/contact/_components/contact-form.tsx#L45>) sets `window.location.href = mailto:…` and immediately shows a success message on line 46, whether or not a mail app opened. Problems:

- Desktop visitors who use Gmail or Outlook in the browser usually have no `mailto:` handler, so nothing happens. They are told the opposite.
- `mailto:` URLs over about 2,000 characters are truncated or rejected by several clients (Outlook desktop, some Windows handlers). The form allows 4,000 characters, about 12,000 once URL-encoded.
- The no-JS fallback submits `name`, `email`, `subject`, `body` as query parameters. Mail apps ignore `name` and `email`, so the sender's details are lost, and spaces arrive as `+`.

This is the site's primary conversion. **Fix:** a Server Action (`useActionState`, the same `contactSchema`) that sends through an email API (Resend, Postmark, or SES), with a honeypot field, a per-IP rate limit, and optionally Cloudflare Turnstile. Show real pending, success, and error states, and keep `mailto:` as the error-state fallback with a **Copy email** button. When the backend lands, also store the message (the `Message` model is already planned in ARCHITECTURE.md). Add `RESEND_API_KEY` (or similar) to `env.ts` and `.env.example`.

## 🟠 P1: high value

### 5. Home page weight: 945 KB of HTML

| Page                     | HTML (raw) | HTML (gzip) | RSC payload |
| ------------------------ | ---------- | ----------- | ----------- |
| `/`                      | 945 KB     | 147 KB      | 472 KB      |
| `/projects`              | 602 KB     | 84 KB       | 318 KB      |
| `/about`                 | 424 KB     | 99 KB       | 229 KB      |
| `/projects/travel-buddy` | 218 KB     | 37 KB       | 116 KB      |
| `/contact`               | 173 KB     | 24 KB       | 101 KB      |
| 404                      | 116 KB     | n/a         | n/a         |

Where it comes from on `/`:

- **241 inline `<svg>` elements carrying 220 KB of path data.** `TechIcon` inlines the full simple-icons path every time a logo appears: marquee (×2 copies), orbit, services, every project card, experience badges. The same paths then appear again in the RSC payload (about 500 KB of `self.__next_f.push`). **Fix:** emit one hidden SVG sprite (`<symbol id="tech-react">…`) per page, or once in the layout, and render `<svg><use href="#tech-react"/></svg>`. Alternatively, serve the icons as static `/icons/*.svg` files through `<img>`, which caches across pages.
- **Featured projects rendered four times.** [featured-projects.tsx:54](../src/components/sections/featured-projects.tsx#L54) renders every card into each of the four tab panels: 20 `<article>`s for 6 projects. Render the list once and filter with a `data-category` attribute plus CSS, or with client state on a single list.
- **`/projects` renders every card twice.** [projects/page.tsx:45](<../src/app/(site)/projects/page.tsx#L45>) passes the full list both as the Suspense `fallback` and as `items` to the client filter, so the cards go into the HTML and again into the RSC payload. One server-rendered list with `data-category` attributes, filtered client-side by hiding items, avoids both copies.

Budget suggestion: home HTML under 150 KB raw (under 40 KB gzipped).

### 6. `zod` ships to the browser on two pages

Chunk `3b0s11hlvkplp.js` (391 KB raw, about 90 KB gzipped) loads on `/projects` and `/contact`.

- `/projects`: [filtered-projects.tsx:12](<../src/app/(site)/projects/_components/filtered-projects.tsx#L12>) imports `PROJECT_CATEGORIES` and `CATEGORY_LABELS` from `@/lib/schemas/content`, which builds every zod schema at import. Move the plain constants (`PROJECT_CATEGORIES`, `CATEGORY_LABELS`, `CONTEXT_LABELS`, `CONTRIBUTION_LABELS`) to a zod-free module such as `src/lib/content-labels.ts`.
- `/contact`: client-side validation imports `contactSchema`. Once #4 moves validation into a Server Action, use native constraint validation (`required`, `minLength`, `type="email"`) on the client, or `zod/mini`.

### 7. Dates are frozen at build time

Every page is static, so these are computed once, when you deploy:

- "Jul 2026 – Present · 3 mo" and the other durations ([dates.ts:35](../src/lib/dates.ts#L35))
- the "4+ years" pill and stat (`yearsSince`, [dates.ts:28](../src/lib/dates.ts#L28))
- the footer © year ([site-footer.tsx:17](../src/components/layout/site-footer.tsx#L17))

A portfolio redeployed every few months will show stale numbers. In January it shows last year's ©. **Fix:** `export const revalidate = 86400` in the root layout (daily ISR, still static), or compute these in a small client component.

`site.description` hard-codes "4+ years" ([site.ts:10](../src/lib/site.ts#L10)) and the Experience section hard-codes "Four years". Derive them from `careerStart` like the stats, per PRODUCT.md's "derive any stat from the content".

### 8. The floating assistant is a placeholder

The 🤖 button sits in the most prominent position on every page. Any question gets "I'm not connected yet: the AI assistant is coming soon" ([chat-panel.tsx:17](../src/components/widgets/chatbot/chat-panel.tsx#L17)). For a recruiter skimming for a minute, a fake feature reads worse than none. **Hide the launcher until it works.** If you build it (see Features), keep this UI: the `useChat` seam is well placed. The `whatsappHref` field on `ChatContact` is passed in but never used.

### 9. Floating buttons cover content on phones

At 375 px the two 56 px floating buttons ([floating-actions.tsx:10](../src/components/widgets/floating-actions.tsx#L10)) overlap the right end of the hero's **Download CV** button, and further down they sit over cards and form controls as you scroll. Keyboard focus can land under them (WCAG 2.2 **2.4.11 Focus Not Obscured**). **Fix:** on phones, show a single button (WhatsApp, or a "Contact" button that opens a small menu), hide it while the hero CTAs are on screen, and add bottom padding to the footer equal to the button stack's height.

### 10. Anonymization: check the inventory screenshot

`public/projects/fulfilment-inventory-platform/inventory-redacted.png` blurs the product name in the page title and in the Product Name field. The **Recent activity** panel (bottom right) still shows it in clear text: `Product "Physical Product "The Band" T-Shirt…`. Two store URLs are also partly visible (`…com`, `…ify.com`). If that product name or store belongs to a client, blur those areas too (PRODUCT.md: no client or product names anywhere). If it's seed or demo data, ignore this.

### 11. Security headers: no CSP

The production response sends `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: DENY`, `Permissions-Policy`, and HSTS, with `X-Powered-By` removed. Good. Missing:

- **Content-Security-Policy.** The site is fully static, so a nonce CSP (which needs dynamic rendering) is overkill. A static policy in `next.config.ts` still blocks most injection impact:
  `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self' mailto:; object-src 'none'; upgrade-insecure-requests`.
  Ship it as `Content-Security-Policy-Report-Only` first, then enforce it. Add the email or analytics hosts to `connect-src` once they exist.
- `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin`.
- HSTS includes `preload`. That's harmless on `*.vercel.app`, but on a custom domain, submitting it to the preload list commits every subdomain to HTTPS. Only keep it if you intend to.

### 12. Motion with no pause control (WCAG 2.2.2)

The tech marquee, both orbit rings, the bobbing pills, and the typewriter all move or update indefinitely. The marquee pauses on hover or `:focus-within`, but its items aren't focusable, so keyboard and touch users can't pause it. Reduced motion stops everything, which is good, but 2.2.2 (Level A) also requires a control for everyone else. **Fix:** a small "Pause animations" toggle (in the footer or next to the theme switch) that sets a `data-motion="paused"` attribute on `<html>`, which CSS uses to pause the animations; Three.js can read the same flag. Or stop the typewriter after one cycle and the marquee after about 30 s.

### 13. Icons and manifest

- `/favicon.ico` → **404**, and the 404 returns a 116 KB HTML page for every favicon request from browsers, crawlers, and RSS readers. Add `src/app/favicon.ico` (48×48 or larger).
- `/apple-touch-icon.png` → **404**. Add `src/app/apple-icon.png` (180×180) so iOS home-screen and share sheets get the monogram.
- `manifest.ts` lists only `icon.svg` ([manifest.ts:13](../src/app/manifest.ts#L13)). Add 192 and 512 PNGs, including a `purpose: "maskable"` one.

### 20. Secrets and repository hygiene

- **`.env` is copied into `.next/standalone/`.** That's Next's default standalone behaviour. If the standalone folder is ever zipped, uploaded, or baked into a Docker image, your local `DATABASE_URL` (with password) goes with it. Keep secrets out of `.env` on build machines, or delete `.next/standalone/.env` in `scripts/copy-standalone-assets.mjs`.
- **`.env.local` holds stale secrets** from an older project (`NEXTAUTH_SECRET`, `NEXTAUTH_URL`, `DIRECT_URL`, a second `DATABASE_URL`). Next loads it during every build ("Environments: .env.local, .env"), and it overrides `.env`. Delete what this project doesn't use.
- **A 16 MB executable is committed** (`.agents/skills/impeccable/scripts/bin/linux-x64/impeccable`, mirrored under `.claude/`) along with a 1.1 MB font index and a 520 KB script. That's most of the 16 MB pack. Vendored third-party binaries in a public portfolio repo are a supply-chain and size cost. Gitignore the `bin/` folder and install it with the skill's own tooling.
